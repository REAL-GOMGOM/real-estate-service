# 과거 실거래 조회 안정화·부분 자료 비교 보호 — 2026-09-06

앞선 합계·기준 시각·홈 동선 개선(`cb5d6b4`)의 후속 작업이다.

## 변경 범위

- 웹의 국토부 라이브 조회에 월 작업 3개, 월별 추가 페이지 2개, 통신 최대 4개와 요청 시작 간격 100ms를 적용한다. 모두 **웹 요청 하나당** 제한이며 전체 사용자·플랫폼의 국토부 호출 한도를 보장하지 않는다.
- 통신 시도마다 응답 본문까지 8초로 제한한다. 라이브 조회는 GET 시작 이후 이미 소비한 시간을 차감한 45초 예산을 쓰고, 라우트 실행 상한은 60초로 둔다. snapshot/index는 기존 개별 timeout을 유지하므로 모든 API 응답이 45초 이내라는 보장은 아니다.
- 기간·거래 유형 변경/화면 이탈의 취소가 게이트 대기, 재시도 지연, 월·페이지 작업, 응답 본문까지 전달된다. 매매 실패 시 형제 작업도 취소한다.
- 매매는 기존 전체 성공 또는 오류 정책을 유지한다. 전월세·분양권의 일반적인 월별 실패는 기존 `status: partial`, `failedMonths`, `no-store`로 응답한다. 취소·전체 예산 초과·시도 timeout 소진은 503/no-store이며 정상 0건 또는 일부 성공으로 바꾸지 않는다. 외부 오류 원문·서비스 키를 응답에 노출하지 않는다.
- 누락된 월과 재조회 버튼을 보여준다. 재조회는 기존 부분 응답 캐시를 건너뛴다. 조건을 바꾸었다가 돌아올 때 거래·기준 시각·완전성 정보를 함께 복원한다.
- 부분 응답의 카드·상세·표·차트·텍스트 공유·이미지 공유는 신고가, 기간 최고가 대비 비율/차액, 최고가 점선을 숨긴다. 관측된 최고/평균·이전 거래는 ‘확인된 거래’로 한정하고 누락 안내를 함께 표시한다. 실제 계약 가격·날짜·면적·검증된 단지 ID/공유 URL은 보존한다.
- 일부 월이 빠졌고 표시할 거래도 없으면 ‘거래가 없다’고 단정하지 않는다. 불완전한 매매 응답이 오더라도 신고가 필터로 모든 기록을 감추지 않는다.
- 맥미니 수집 작업의 기본 옵션·4회 재시도는 변경하지 않는다. 2개월 공개 snapshot 범위, 정확 단지 검증, snapshot serving mode에서 오래된 DB로 폴백하지 않는 정책도 유지한다.
